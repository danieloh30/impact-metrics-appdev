# RUN metrics — Quarkus workbook and agent workflow

## Month-end reporting and pivot charts

SharePoint runs use DA metric model 2026 in the separate AppDev Advocacy impact metrics workbook as the authoritative source of activity units, weights and trailing eligibility. Never use AvocadoBot's older DA metric model or guess an absent rule. Geography comes from the historical workbook's Ranges author lookup. Missing rules remain explicit exclusions.

Reporting uses the selected month's last day, after that month has closed. A live measurement collected later cannot establish a past month-end value. The selected monthly input sheet is treated as a user-accepted month-end snapshot only when its named month matches the reporting month. Sheet names do not independently prove observation dates; show this limitation. Older available monthly sheets remain baselines, not selected-month totals. Missing or ambiguous month-end totals require an explicit dated user confirmation. Keep its as-of date separate from when the confirmation was entered. Preserve original workbook and agent values for audit.

Current one-time attendance uses its already allocated attendance-hours result without multiplying duration or allocating again. Ignore the sales-delivered workshop exception: AppDev does not submit that activity. Markus blog data and Elder blog data contributions are one-time inputs for the selected month: Trailing 90-day = No, no Current total or Previous total, exact attributed views × the applicable model weight. Other digital current contributions use the month-end total minus its previous total, once. Historical growth uses the month-end total minus the preceding total, once, then the model weight. Compute impact from exact values before rounding reported views. Do not remove zero-impact LinkedIn rows for expiration.

Unresolved follow-ups, retained historical inputs without verified growth, absent model rules, unavailable month-end totals and negative deltas are excluded from pivots with reasons. Reporting month is distinct from original activity date. Combined reporting gives current contributions precedence over matching historical activity/author/tool rows and excludes duplicate attribution keys. Keep independent current and historical-growth scopes available.

Build three SUM pivots: Type of activity / Impact hours; Tool / Impact hours; and Type of activity / Views / attendance filtered solely to Tool = IBM Bob. Preserve unit labels because Bob measures vary by activity. SPA charts, reporting detail and on-demand Excel/CSV downloads use the same exact eligible aggregates. Excel includes typed source rows, native SUM PivotTables and cached charts. Processing remains structured; no intermediate CSV files are created.

## Phase 1: digital content metrics calculation

DigitalMetricsAgent processes these activity types: 3rd party conference video; Blog post / slide shares / .io updates; Digital conference / event; Livestream; Podcast or webinar (internal / external); Recorded video; Demos (archive / GitHub); Development - tools, add-ons (Registry); Development - tools (GitHub); Forum answer (IBM or practitioner community); Twitter / Facebook / LinkedIn / BlueSky / Weibo.

With a URL, use the supported provider collectors: YouTube views, DZone article Views, LinkedIn post reactions, GitHub stars, and Terraform Registry downloads. LinkedIn Live events require Video Views from post analytics, never lifetime unique viewers. Unsupported, inaccessible, or unavailable resource measurements go exclusively to follow-up.csv for verified entry, retry, or acknowledgment.

Without a URL, supplied numeric Views / attendance AND Duration (in hours) satisfy current-month collection. Preserve the supplied view count and record input evidence; do not create a No URL manual-collection issue. Zero views is valid. Invalid supplied numbers require correction. A missing field still requires collection. Digital views remain views; multiplying duration into attendance hours applies to in-person activities only.

Store digital and follow-up result datasets with source columns and provenance. Their download filenames are digital.csv and follow-up.csv. Pause for user approval in the SPA.

## Phase 2: in-person event calculation

AttendanceAgent processes Booth duty; Conference keynote or breakout (proprietary or 3rd party); Conference workshop (proprietary or 3rd party); CSP or other partner presentation (digital or in-person); Customer meeting; Customer workshop; Customer presentation; Internal team member enablement; Meetup (user group).

Booth duty goes to follow-up.csv pending verified Field Marketing leads. For other in-person activities, calculate Attendance hours = Views / attendance × max(Duration (in hours), 1). Blank duration defaults to one hour. A URL is not required. Attendance must be numeric and nonnegative; a supplied nonnumeric duration requires correction. Store the in-person result dataset (download filename in-person.csv) and pause for approval.

## Phase 3: splitting of entries

AttributionAgent splits explicit semicolon-separated or line-separated Author of activity and Tool values inside cells into the Cartesian product. Commas inside names, titles, or other text do not define columns or attribution boundaries. A single cell value remains one value. For digital activities, allocate Views / attendance across authors × tools. For in-person activities, allocate Attendance hours into Views / attendance. Use six-decimal conserved allocation with a remainder so totals are unchanged. Follow-up attribution is split without inventing or recalculating metrics. Pause for approval.

## Phase 4: trailing 90-day calculation

Trailing90Agent processes prepared historical rows when present. Move historical Current total to Previous total, collect a fresh total once per shared resource URL, allocate it across that URL's rows, and subtract each previous baseline into Views / attendance. Current-month no-URL input evidence must not be reused as a fresh historical lifetime total. Missing fresh totals require collection; missing/invalid/negative baselines block approval until corrected. Negative deltas remain visible with a review note. Store the updated historical result dataset (download filename updated_90-day.csv) and pause for approval. Skip this phase when no historical rows were selected.

Historical rows without URLs and with valid supplied nonnegative Views / attendance proceed automatically, keeping supplied views and the recorded total with Supplied historical input — not a trailing delta provenance. No baseline or duration is required for this path. Missing or invalid supplied views still require review. For unresolved historical rows without URLs, the SPA shows the original Views / attendance, available Duration (in hours), and recorded baseline. The user may explicitly keep valid original input values or edit attendance/duration, then approve the refreshed phase. Save that per-row review decision without rewriting source data. Such rows do not claim a fresh lifetime total or trailing delta; retain the recorded total unchanged and label Metric basis as retained/reviewed input. A baseline is not required when no delta is being calculated. Always include Original Views / attendance and Original Duration (in hours) in the historical export, including unresolved rows. Missing/invalid supplied input values must be edited to valid nonnegative numbers before this choice can resolve review. URL-based fresh total collection and baseline validation remain unchanged.

## Historical eligibility and review context

Within the selected monthly snapshot and date window, Trailing 90-day = No (or other non-Yes flag) rows are excluded from preparation and Phase 4 refresh, exports, and review issues. Yes/true/1 includes a row; a blank flag includes digital types only. Legacy already-selected inputs lacking the flag column retain compatibility. Do not re-collect one-off in-person rows marked No, or use AvocadoBot data to overwrite a historical attributed metrics row. Historical decimal views below one can be valid conserved author/tool shares; retain exact shares internally and round reported Views / attendance up to integers only after calculations; do not invent missing durations.

Preserve the actual Current total cell value, including blanks or invalid text. Never write a review message into a numeric baseline cell. Missing baselines block only a delta calculation: configured content exclusions retaining supplied inputs do not require one. Existing verified fresh measurements for non-excluded sources still require a valid baseline. Excluded content always bypasses lifetime/delta collection and baseline review, even with cached measurements. Preserve workbook views; explicit manual overrides may supply content views allocated across the URL group. Ignore old automatic measurements for excluded sources. Review popups identify source workbook, sheet, row, author, and tool; Enter baseline always edits the baseline even when URL is blank. Numeric editors start blank for invalid values. Existing saved runs apply the eligibility and collection policies on a phase retry without altering immutable source or approved earlier results.

Historical verified measurements default to the previous Current total or latest saved measurement, expressed as this attributed row's share. Convert a confirmed share to the shared resource total once before the existing group allocation; do not divide the previous share again. Baseline corrections are independent. Historical input retention validates and edits duration only when the original row has the Duration (in hours) column; absent duration is not required or fabricated. Resource links support safe HTTP/HTTPS browser navigation while automatic collection retains its HTTPS restriction.

Preserve raw workbook values, historical baselines, durations, and internal precision. Preview and CSV/ZIP downloads use the same rounding; current.csv Current total mirrors its rounded views. Per-row rounding can increase reported aggregate totals. Negative deltas retain their warning even when their rounded value is zero. Public HTTP resource URLs are upgraded to HTTPS for automatic collection; do not show the obsolete HTTPS-only manual warning.
